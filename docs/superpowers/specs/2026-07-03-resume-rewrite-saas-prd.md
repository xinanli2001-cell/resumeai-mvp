# AI 简历修改工具 PRD

日期：2026-07-03  
状态：已确认产品骨架，待用户审阅文档  
产品形态：SaaS 雏形  
目标用户：留学生 / 应届生求职者

## 1. 产品概述

### 1.1 产品定位

本产品是一个面向留学生和应届生的 AI 简历修改 SaaS。用户先建立个人信息库，再输入目标岗位 JD。系统根据 JD 从信息库中推荐最相关的经历，按完整经历块进行 STAR 改写，用户确认后进入简历编辑页面，最终基于模板生成并导出简历。

产品重点不是给简历打分，而是帮助用户完成“从个人经历到岗位定制简历”的闭环。

### 1.2 核心价值

- 降低用户为不同岗位重复修改简历的成本。
- 让项目、实习、工作经历可沉淀、复用、组合。
- 让 LLM 改写有事实约束，避免直接胡编。
- 支持中英双语，适配中国和海外求职场景。
- 为后续商业化预留账号、额度、管理员和模板能力。

### 1.3 非目标

- MVP 不做简历评分。
- MVP 不做支付订阅、发票、退款。
- MVP 不做 Word/PDF 上传后自动还原模板。
- MVP 不做 Cover Letter 和面试素材包。
- MVP 不做复杂运营后台、成本看板、审计日志。

## 2. 用户与场景

### 2.1 核心用户

- 留学生 / 应届生。
- 有多个课程项目、个人项目、科研项目、实习经历。
- 需要针对不同 JD 生成不同版本的简历。
- 不确定哪些经历最适合某个岗位，也不擅长 STAR 写法。

### 2.2 典型场景

1. 用户将已有简历或经历文本导入个人信息库。
2. 系统将自由文本拆解为结构化字段，用户确认后保存。
3. 用户粘贴目标岗位 JD。
4. 系统高亮推荐匹配经历，并显示匹配理由。
5. 用户可以接受推荐，也可以从非推荐经历中手动选择。
6. 系统按完整经历块生成 STAR 改写结果。
7. 用户逐个确认、编辑或拒绝改写后的经历块。
8. 用户进入简历编辑页，左侧查看个人信息库，右侧编辑完整简历。
9. 用户选择或自定义模板，预览后导出 PDF。

## 4. 核心流程

### 4.1 主链路

```mermaid
flowchart LR
  A["建立个人信息库"] --> B["输入目标 JD"]
  B --> C["系统推荐经历"]
  C --> D["用户选择经历"]
  D --> E["LLM 按经历块改写"]
  E --> F["用户确认改写结果"]
  F --> G["进入简历编辑页"]
  G --> H["预览并导出 PDF"]
```

### 4.2 两步确认流

第一步是 AI 改写结果确认页。用户在这里看到每段经历的推荐理由、原始内容、改写内容和风险提示，按经历块确认。

第二步是简历编辑页。页面左侧是个人信息库，右侧是完整简历编辑 / 预览区域。用户可以继续调整模块、模板和文字。

### 4.3 最小修改单元

AI 改写和用户确认的最小单元是一段完整经历，而不是单条 bullet。例如：

- 一个 1-3 月完成的项目。
- 一次完整实习经历。
- 一个工作阶段。
- 一个课程 / 科研项目。

每个经历块内部可以包含项目描述、职责、行动、成果、技术栈、关键词和 STAR 结构，但确认动作以完整经历块为单位。

## 5. 功能需求

### 5.1 账号与权限

用户可以注册、登录、退出登录。所有个人信息库、简历版本、模板和生成记录必须归属到用户账号。

管理员账号拥有无限使用额度，并可以进入最小后台管理用户额度和生成记录。

验收标准：

- 普通用户只能访问自己的数据。
- 未登录用户不能访问信息库和简历编辑页。
- 管理员不受生成额度限制。
- 普通用户超过额度后不能继续调用 LLM，页面提示额度不足。

### 5.2 个人信息库

个人信息库是所有简历版本的事实来源。

字段范围：

- 基本信息：姓名、头像/可选、所在地、求职意向、个人简介。
- 联系方式：电话、邮箱、LinkedIn、GitHub、个人网站。
- 求职属性：目标城市、签证 / 工作权限、语言能力。
- 教育经历：学校、专业、学历、时间、核心课程、GPA / 排名、成果。
- 项目经历：项目名称、周期、角色、背景、任务、行动、结果、技术栈、量化成果、标签。
- 实习 / 工作经历：公司、岗位、部门、时间、职责、成果、技术栈、协作对象、标签。
- 职业能力：技能、证书、工具、软技能、关键词标签。

验收标准：

- 用户可以新增、编辑、删除、归档每类信息。
- 项目、实习、工作经历以可复用模块存在。
- 每段经历可被多个简历版本引用。
- 简历版本引用经历时，应保存当时的改写快照，避免后续信息库修改直接污染历史简历。

### 5.3 自由文本导入与 AI 拆解

用户可以粘贴一段原始经历文本。系统调用 LLM 将其拆解为结构化字段，并进入确认表单。

验收标准：

- AI 拆解结果必须可编辑。
- 用户确认前，不自动写入正式信息库。
- 无法确定的信息应标为“待确认”，不能伪造。
- 用户可以放弃本次导入。

### 5.4 JD 解析与经历推荐

用户输入目标岗位 JD 后，系统提取职责、技能、关键词、岗位类型和优先级信号。

系统从个人信息库中推荐匹配经历，推荐项高亮展示。用户仍可从全量经历中选择非推荐项。

验收标准：

- 推荐项展示匹配理由。
- 匹配理由至少包含命中的技能、职责或行业关键词。
- 用户可以取消推荐项。
- 用户可以添加非推荐经历。
- 只有用户最终选择的经历进入改写阶段。

### 5.5 LLM 改写策略

默认模式是“合理补全”。LLM 可以基于上下文提出技术栈、方法论、量化口径等补充建议，但不确定内容必须标记为待用户确认。

包装模式是独立开关，默认关闭。用户主动开启后，系统可以更强地优化表达、突出影响力和岗位相关性，但仍不能虚构公司、证书、项目、硬指标或用户未确认的事实。

验收标准：

- 默认模式下，不直接新增未经确认的事实。
- 包装模式开启前，有真实性提示。
- 改写结果保留原始经历对照。
- 每段经历显示“确认 / 编辑 / 拒绝”操作。
- 每段经历可以输出中文、英文或双语版本。

### 5.6 改写结果确认页

改写结果页出现在简历编辑页之前。它负责让用户审核 AI 生成内容。

页面需要展示：

- 当前 JD 摘要。
- 用户已选择的经历块。
- 每段经历的匹配理由。
- 原始内容。
- STAR 改写结果。
- 待确认补全项。
- 包装模式状态。
- 确认、编辑、拒绝操作。

验收标准：

- 用户至少确认一段经历后，才能进入简历编辑页。
- 被拒绝的经历不进入当前简历。
- 用户编辑后的版本进入简历编辑页。
- 页面能区分“AI 原始建议”和“用户确认版本”。

### 5.7 简历编辑页

简历编辑页采用左右结构：

- 左侧：个人信息库，包括基本信息、联系方式、教育、项目、实习、工作、职业能力。
- 右侧：完整简历编辑 / 预览区域。

用户可以从信息库拖入或选择模块，调整模块顺序，修改文字，切换模板，预览 PDF 效果。

验收标准：

- 用户能编辑简历中的文字。
- 用户能调整模块顺序和显示 / 隐藏模块。
- 用户能从个人信息库添加更多经历。
- 用户能保存当前简历版本。
- 用户能导出 PDF。

### 5.8 模板自定义

MVP 支持平台内模板编辑器，不支持上传 Word/PDF 自动还原。

用户可以从系统模板开始，调整并保存为“我的模板”。

可配置项：

- 模块顺序。
- 字体、字号。
- 间距。
- 颜色。
- 标题样式。
- 页眉基础样式。

验收标准：

- 用户可以保存自定义模板。
- 用户可以在不同简历版本中复用自定义模板。
- 模板配置不应改变用户信息库原始数据。
- 导出 PDF 使用当前模板。

### 5.9 额度与用量

普通用户拥有免费额度。每次 LLM 调用都要记录用途和消耗。管理员账号无限使用。

记录字段：

- 用户。
- 调用类型：导入拆解、JD 解析、经历推荐、经历改写、翻译等。
- 时间。
- 状态。
- 消耗量。
- 关联对象。

验收标准：

- 额度不足时阻止继续生成。
- 管理员不受限制。
- 后台可以查看用户用量。
- 数据模型预留套餐 / 额度扩展能力。

### 5.10 最小管理员后台

管理员后台只做 MVP 运营所需的最小功能。

功能：

- 查看用户列表。
- 查看用户额度。
- 调整用户额度。
- 设置或取消管理员身份。
- 查看 LLM 生成记录与用量。

验收标准：

- 非管理员不能访问后台。
- 管理员可以调整普通用户额度。
- 管理员操作不影响简历内容数据。

## 7. UI / UX 要求

### 7.1 信息库页面

信息库页面要让用户感觉是在维护长期资产，而不是临时填表。

要求：

- 分类清晰：基本信息、联系方式、教育、项目、实习、工作、职业能力。
- 项目 / 实习 / 工作经历以卡片模块展示。
- 支持自由文本导入入口。
- 支持 AI 拆解后的结构化确认。
- 每段经历显示标签和最近使用情况。

### 7.2 JD 匹配页面

要求：

- 左侧或上方输入 JD。
- 系统显示解析出的岗位关键词。
- 推荐经历在列表中高亮。
- 高亮不等于强制选择。
- 非推荐经历也可手动选择。

### 7.3 改写结果确认页

要求：

- 每个经历块是一个审核卡片。
- 显示原文、改写结果、匹配理由、待确认补全项。
- 支持确认、编辑、拒绝。
- 包装模式开关在生成前展示，默认关闭。

### 7.4 简历编辑页

要求：

- 左侧是个人信息库。
- 右侧是简历编辑 / 预览。
- 支持模板切换和模板自定义。
- 支持保存和导出 PDF。
- 不展示评分入口。

## 8. 非功能需求

### 8.1 隐私与安全

- 简历、联系方式、JD、生成记录属于敏感数据。
- 用户数据必须隔离。
- 管理员后台不能暴露密码或敏感认证信息。
- LLM 调用日志不应泄露用户密码、密钥或支付信息。
- 需要提供删除账号或删除个人信息库数据的能力。

### 8.2 可用性

- 关键生成步骤失败时，用户不能丢失已输入内容。
- 长文本生成需要显示加载状态。
- AI 输出必须允许人工编辑。

### 8.3 可扩展性

- 额度系统预留套餐能力。
- 模板系统预留模板市场能力。
- LLM 调用层应可替换模型提供商。
- 数据结构支持后续 Cover Letter 和面试素材包复用。

## 9. 成功指标

MVP 阶段关注产品闭环是否成立，而不是收入。

- 新用户完成信息库首次录入率。
- 用户从输入 JD 到生成第一份简历的完成率。
- AI 推荐经历被用户接受的比例。
- AI 改写经历块被确认 / 编辑 / 拒绝的比例。
- PDF 导出完成率。
- 单份简历平均 LLM 调用成本。

## 11. MVP 任务拆分

### Task 1：项目基础与账号体系

目标：建立 SaaS 应用基础。

范围：

- 用户注册、登录、登出。
- 用户角色：普通用户 / 管理员。
- 用户数据隔离。
- 基础布局和导航。

验收：

- 普通用户只能访问自己的页面和数据。
- 管理员能进入后台入口。
- 未登录用户会被引导登录。

### Task 2：个人信息库

目标：让用户维护长期可复用的个人信息资产。

范围：

- 基本信息和联系方式。
- 教育、项目、实习、工作、职业能力模块。
- 新增、编辑、删除、归档。
- 标签和结构化字段。

验收：

- 用户能完整录入一份基础档案。
- 用户能录入多个项目和实习经历。
- 每段经历能被后续简历流程引用。

### Task 3：自由文本导入与 AI 拆解

目标：降低信息库录入成本。

范围：

- 粘贴原始文本。
- 调用 LLM 拆解为结构化字段。
- 用户确认后保存。

验收：

- AI 结果可编辑。
- 不确定字段标为待确认。
- 未确认内容不进入正式信息库。

### Task 4：JD 解析与经历推荐

目标：从岗位要求中推荐最相关经历。

范围：

- JD 输入。
- JD 关键词 / 技能 / 职责解析。
- 经历匹配排序。
- 推荐经历高亮和匹配理由。
- 用户可选推荐和非推荐经历。

验收：

- 系统能推荐经历并解释原因。
- 用户能手动调整最终选择。
- 只有选中经历进入改写。

### Task 5：经历块 STAR 改写确认

目标：生成可控、可确认的岗位定制经历。

范围：

- 默认合理补全模式。
- 包装模式开关。
- 中英双语生成。
- 原文 / 改写 / 匹配理由 / 待确认项展示。
- 确认、编辑、拒绝。

验收：

- 每段经历以完整经历块为单位处理。
- 用户确认版本进入简历编辑页。
- 被拒绝经历不进入当前简历。
- 包装模式有风险提示。

### Task 6：简历编辑器与模板系统
