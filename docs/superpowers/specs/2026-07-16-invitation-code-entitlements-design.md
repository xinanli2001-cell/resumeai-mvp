# ResumeAI Invitation Code Entitlements Design

Date: 2026-07-16

## Goal

Provide a durable invitation-code system for two lifecycle stages:

- A closed beta where a valid code is required to create an account.
- An open product where codes remain available as a relationship and customer
  benefit that grants additional AI rewrite quota.

The system must make each redemption auditable, prevent a code from exceeding
its capacity, and preserve the benefit after a user signs out or refreshes.

## Scope

This change adds invitation-code creation and management for administrators,
code redemption during registration and from account settings, and quota
entitlements for redeemed codes.

It does not add payments, subscriptions, organization accounts, referral
rewards, email delivery, or an invite-only feature set beyond rewrite quota.

## Data Model

### InvitationCode

Each invitation code has:

- `id`: opaque database identifier.
- `code`: unique uppercase human-shareable code generated by the server.
- `label`: administrator-only description such as `July beta friends`.
- `maxUses`: positive integer capacity.
- `usedCount`: number of successful redemptions.
- `bonusQuota`: positive integer rewrite quota granted per redemption.
- `active`: whether new redemptions are allowed.
- `expiresAt`: optional expiration timestamp.
- `createdAt` and `updatedAt` timestamps.

### InvitationRedemption

Each successful code use is an immutable record with:

- `id`.
- `invitationCodeId` and `userId`.
- `redeemedAt` timestamp.
- `bonusQuota`: the grant captured at redemption time.

`@@unique([invitationCodeId, userId])` prevents one account from redeeming the
same code more than once. Users may redeem distinct active codes; each grant
adds to their existing quota limit.

Redeemed codes are never deleted from the admin UI. Administrators can stop
future use by setting `active` to false.

## Configuration

`REGISTRATION_MODE` is a validated environment setting with two values:

- `open` (default): a new account may register without a code; a supplied code
  is redeemed as an optional benefit.
- `invite_only`: registration requires a valid invitation code.

This setting controls only registration. Existing signed-in users can redeem a
valid code from Settings in either mode.

## User Flows

### New Registration

The public registration form gains an optional invitation-code field. In
`invite_only` mode the field is required and its validation message explains
that an invitation is necessary.

After email/password validation, the server normalizes the submitted code by
trimming whitespace and converting it to uppercase. In one database
transaction it:

1. validates code existence, active status, expiration, and remaining capacity;
2. reserves one use without allowing `usedCount` to exceed `maxUses`;
3. creates the User and Profile;
4. creates the immutable redemption record when a code was supplied;
5. increases the new user's `quotaLimit` by the code's `bonusQuota`.

If the code cannot be reserved, no user account is created. In open mode, an
empty code skips redemption and creates the account normally.

### Existing User Redemption

Settings gains a compact `兑换邀请码` section. The signed-in user submits one
code, receives a success or actionable error message, and sees the updated
available rewrite quota. The same transaction rules apply; attempting to
redeem the same code twice returns a conflict without changing quota.

## Administration

The existing `/admin` area gains an invitation-code management panel:

- Create a code by entering label, max uses, bonus quota, and optional expiry.
- Copy the generated code after creation.
- View active/expired status, use count, capacity, grant amount, and recent
  redemption emails/times.
- Deactivate an active code; this prevents future redemption but retains its
  history.

Only `ADMIN` users may access the panel or its API routes. Regular users never
receive invite-code lists, other users' redemption data, or admin labels.

## Consistency And Security

Code matching is case-insensitive because the server stores and compares the
normalized uppercase representation. Code capacity is reserved with a guarded
database update inside the transaction, so simultaneous requests cannot both
claim the final available use. A failed registration or redemption rolls back
the reservation, user creation, quota change, and redemption record together.

The API returns generic validation messages for invalid, inactive, expired,
used-up, or previously redeemed codes. It never returns database identifiers or
quota details for a code to an unauthenticated caller.

The existing quota service remains the enforcement point for rewrite use. The
new system only increases `User.quotaLimit`; it does not change admin unlimited
quota behavior, LLM provider selection, rate limits, or logging rules.

## API Boundaries

- `POST /api/auth/register`: accepts optional `invitationCode`; enforces
  `REGISTRATION_MODE` and invokes the invitation redemption service.
- `POST /api/invitations/redeem`: authenticated user redemption endpoint.
- `GET /api/invitations/me`: authenticated user quota and redemption summary
  for Settings.
- `GET /api/admin/invitations`, `POST /api/admin/invitations`, and
  `PATCH /api/admin/invitations/[id]`: administrator-only management endpoints.

The invitation service owns normalization, validation, guarded capacity
reservation, redemption creation, and quota updates. Routes only authenticate,
validate request payloads, and map errors to HTTP responses.

## Testing And Acceptance

Unit coverage must prove:

- open registration works with no code;
- invite-only registration rejects no code;
- a valid code grants the configured quota exactly once;
- duplicate redemption by one user changes nothing;
- inactive, expired, and exhausted codes change nothing;
- concurrent final-use attempts result in exactly one successful redemption;
- administrators can create/deactivate codes and non-admins are rejected.

Playwright coverage must prove:

- invite-only registration displays and enforces the code field;
- an existing user can redeem a valid code from Settings and see the new quota;
- an admin can create and deactivate a code;
- switching to open registration lets a user register without a code.

## Non-Goals

- Payments, subscriptions, invoices, and refunds.
- Referral commissions or rewards.
- Emailing invitations.
- Feature flags other than registration access mode.
- Resume scoring, template marketplace, or file-upload parsing.
