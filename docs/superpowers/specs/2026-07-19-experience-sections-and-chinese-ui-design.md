# ResumeAI 经历三模块与全站中文界面设计

日期：2026-07-19
状态：用户已确认（2026-07-19）
适用范围：`web/` 用户界面、经历录入与展示

## 1. 背景

当前信息库中的经历卡片直接展示 `rawText`，AI 导入内容因此混有
`Responsibility:`、`Achievement:` 等英文前缀，信息层级不清晰。手动新增经历
也只有“原始描述”和“量化结果”，无法稳定形成“背景、职责、成果”结构。

同时，应用仍存在 `Profile`、`Experience`、`blocks`、`Sign In`、`Sign Out`、
`Create Account` 等英文用户界面文案，与当前以中文为主的产品体验不一致。

## 2. 目标

1. 所有经历在新增、编辑、AI 导入和卡片展示时统一采用“背景 / 职责 / 成果”。
2. 保持现有经历、匹配和改写数据兼容，不进行破坏性数据库迁移。
3. 将 ResumeAI 全站面向用户的静态界面文案统一为中文。
4. 保留品牌、行业缩写、技术名词和用户内容的原始表达。

## 3. 非目标

- 不引入多语言切换或完整 i18n 框架。
- 不翻译用户输入、简历原文、AI 生成内容、邮箱和邀请码。
- 不翻译 `ResumeAI`、`AI`、`JD`、`PDF`、`STAR`、`API`、`LinkedIn`、
  `GitHub`、`DeepSeek` 等品牌、缩写或技术名词。
- 不改变 Prisma 枚举、数据库字段或 API 的英文协议值。
- 不重新设计现有信息架构、导航结构或视觉主题。

## 4. 方案选择

### 4.1 经历数据

采用现有 `structuredFields` JSON 作为三模块的结构化来源：

```ts
{
  summary: string;
  responsibilities: string[];
  achievements: string[];
  pendingClaims?: string[];
}
```

不新增数据库列。这样可直接复用 AI 导入已有的数据形状，同时避免 SQLite 与
PostgreSQL 双迁移。

### 4.2 中文界面

采用“中国单语言 + 共享领域映射”：

- 页面自身的静态文案直接使用中文。
- 经历类型、用户角色、邀请码状态、改写状态等重复枚举使用共享中文映射。
- 不引入语言包加载、路由 locale 或运行时翻译依赖。

## 5. 经历录入与编辑

手动新增和编辑经历时使用以下字段：

- 类型：显示中文选项，提交值保持现有英文枚举。
- 标题、组织、角色、开始时间、结束时间：保持现有字段。
- 背景：多行文本，一个完整背景段落。
- 职责：多行文本，每行一项。
- 成果：多行文本，每行一项。
- 技能、标签：保持现有逗号分隔方式。

保存时：

1. 将背景、职责、成果写入 `structuredFields`。
2. 同步生成规范化 `rawText`，供现有匹配、改写和快照链路继续使用。
3. `rawText` 使用中文模块标题，不再生成英文 `Responsibility:` 或
   `Achievement:` 前缀。
4. 编辑旧经历并保存后，将其升级为新结构。

## 6. 经历卡片

采用用户确认的 A 方案：纵向分区。

卡片顺序为：

1. 经历类型、标题、组织/角色/时间和编辑操作。
2. 背景：普通段落。
3. 职责：项目符号列表。
4. 成果：项目符号列表。
5. 技能与标签。

卡片不再直接整块输出 `rawText`，也不再显示英文前缀或 `0 blocks / 1 blocks`。
空模块不显示空标题。桌面端保持单列阅读顺序，移动端使用同一顺序自然换行，
不引入折叠交互。

## 7. 旧数据兼容

经历展示通过一个纯转换函数产生统一视图模型，规则按优先级执行：

1. 若 `structuredFields` 包含有效的 `summary`、`responsibilities` 或
   `achievements`，优先使用这些值。
2. 否则识别旧 `rawText` 中的 `Responsibility:` 与 `Achievement:` 行，分别
   归入职责和成果；其余非空行合并为背景。
3. 若 `rawText` 不含旧前缀，将全部内容作为背景。
4. 旧 `metrics` 仅在没有结构化成果时作为成果回退，避免重复展示。
5. 转换只影响界面展示；未编辑的旧数据不会被后台静默改写。

`LibraryPage` 必须把 `structuredFields` 安全序列化给客户端。解析器应接受空对象、
未知字段和不符合预期的 JSON 值，并回退到旧数据规则，不能导致页面崩溃。

## 8. 全站中文化规则

扫描 `web/src/app` 及其共享组件中的用户可见静态文案，覆盖：

- 登录、注册和退出；
- 信息库和首次使用引导；
- JD 匹配与 AI 拆解；
- STAR 改写确认；
- 简历列表、编辑、模板和 PDF 导出；
- 设置、隐私和账号删除；
- 管理后台、用户、邀请码和活动记录；
- 加载、成功、空状态、校验与错误反馈；
- 表头、按钮、状态、数量单位和枚举标签。

显示要求：

- `Sign In` → `登录`
- `Sign Out` → `退出登录`
- `Create Account` → `创建账号`
- `Profile` → `基本信息`
- `Experience` → `经历`
- `blocks` → `项`
- 经历类型、角色和状态均通过共享映射显示中文。

API 和数据库仍可返回英文枚举或内部错误码；界面边界负责转成中文。开发日志、
测试名称、代码标识符和运维文档不属于用户界面，不做机械翻译。

## 9. 组件边界

新增或提取两个小型共享单元：

1. 经历展示转换器：把 `rawText`、`structuredFields`、`metrics` 转成
   `{ background, responsibilities, achievements }`。
2. 领域中文标签：集中维护重复的类型、角色和状态映射。

页面组件只负责渲染和交互，不重复实现旧文本解析规则。既有 API 继续接受
`structuredFields`，无需新增路由。

## 10. 错误处理

- 职责和成果按换行拆分，去除首尾空白与空行。
- 背景为空时允许只保存职责或成果，但至少应有标题或现有服务要求的必填信息。
- 旧数据解析失败时将原始文本完整显示为背景，不丢失用户内容。
- 中文化不得改变 HTTP 状态码、权限判断、邀请码规则或额度计算。

## 11. 测试与验收

使用测试先行方式完成：

1. 转换器单元测试先覆盖结构化数据、旧英文前缀、纯背景、metrics 回退和异常
   `structuredFields`。
2. 组件或 E2E 测试验证新增、编辑和 AI 导入后的卡片均显示背景、职责、成果。
3. 验证类型下拉显示中文但请求仍提交英文枚举。
4. 增加用户界面文案回归检查，至少阻止已知英文文案重新出现。
5. 验证 375px 移动端无文字重叠或页面级横向溢出。
6. 运行完整门禁：

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm test:e2e
```

## 12. 验收结论标准

只有以下条件全部满足才算完成：

- 新增、编辑和 AI 导入经历均使用背景、职责、成果结构。
- 当前 staging 中已有的 ResumeAI 项目经历能正确归类，不丢内容、不重复成果。
- 所有经历卡片不再显示 `Responsibility:`、`Achievement:` 和 `blocks`。
- 全站用户界面不存在应翻译而未翻译的静态英文文案。
- 品牌名、缩写、技术名词和用户内容未被误翻译。
- 既有匹配、改写、简历和权限流程不回归。
- 自动化门禁全部退出码为 0。
